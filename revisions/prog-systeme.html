Savoir utiliser man et savoir où regarder

En deux phrases

man est la documentation installée sur la machine : chaque fonction a une page, toujours découpée dans les mêmes rubriques. Le jour de l'examen, tu n'as pas besoin de tout retenir : il faut savoir quelle page ouvrir et quelle rubrique lire.

1. Les sections : le numéro qui change tout

Le piège n°1

Sans numéro, man ouvre la première section qui a une page de ce nom. man printf, man write, man stat ou man kill ouvrent la commande shell (section 1), pas la fonction C. Toujours taper la section : man 3 printf, man 2 write, man 2 stat. En haut de la page, WRITE(2) ou WRITE(1) te dit dans quelle section tu es.

Comment savoir si c'est 2 ou 3 ? Si la fonction parle directement au noyau (descripteurs, processus, mémoire brute), c'est 2. Si c'est une fonction « confort » de la libc (FILE*, chaînes, environnement, annuaire), c'est 3. Dans le doute : man -f nom (ou whatis nom) liste toutes les sections où il existe.

Sauter directement à une rubrique

Tape /^RETURN ou /^ERRORS : le ^ veut dire « en début de ligne », ce qui évite de tomber sur le mot au milieu du texte.

Commandes utiles
  • man -k mot (ou apropos mot) : chercher une page quand on ne connaît pas son nom. Ex. man -k duplicate trouve dup(2).
  • man -f nom (ou whatis nom) : dans quelles sections existe ce nom.
  • man 2 syscalls : la liste de tous les appels système.
  • man 2 open | grep -n O_APPEND : chercher sans ouvrir la page.

5. Défis chronométrés : 1 minute chacun

Ouvre un terminal, lance un chrono, cherche la réponse dans man, puis seulement ensuite clique pour vérifier.

Quels #include faut-il pour waitpid ?

man 2 waitpid → SYNOPSIS : #include <sys/wait.h>.

Que renvoie waitpid avec WNOHANG si le fils tourne encore ?

man 2 wait → /^RETURN : 0.

Quel errno si on ouvre sans O_CREAT un fichier qui n'existe pas ?

man 2 open → /^ERRORS puis /ENOENT : ENOENT.

Que renvoie sbrk en cas d'erreur ?

man 2 sbrk (c'est la page brk) → RETURN VALUE : (void *) -1 et errno = ENOMEM.

Quels sont les champs de struct dirent ?

man 3 readdir → DESCRIPTION : d_ino, d_off, d_reclen, d_type, d_name[256]. Seuls d_name et d_ino sont garantis par POSIX ; d_type peut valoir DT_UNKNOWN, d'où l'usage de lstat.

Quelle macro teste un lien symbolique, et sur quel champ ?

man 7 inode → /S_ISLNK : S_ISLNK(st.st_mode).

Quel champ de struct flock donne le type de verrou ?

man 2 fcntl → /Advisory : l_type (F_RDLCK, F_WRLCK, F_UNLCK).

Le fils hérite-t-il des verrous fcntl du père ?

man 2 fork → /record locks : non.

Après un fork, le fils et le père partagent-ils l'offset d'un fichier ?

man 2 fork → /open file desc : oui, même « open file description », donc mêmes flags et même offset.

_exit vide-t-il les tampons de printf ?

man 2 _exit → /stdio : non, les flux stdio ne sont pas vidés. exit(3), lui, les vide.

Quel format strftime donne le jour de la semaine abrégé ?

man 3 strftime → /%a : %a.

Faut-il le droit de lecture sur un fichier pour faire stat dessus ?

man 2 stat → DESCRIPTION : non, aucun droit sur le fichier lui-même, seulement le droit d'exécution (traversée) sur les répertoires du chemin.

Dans quelle page est documenté execvp ?

man -f execvp → exec(3). C'est une fonction de la libc qui finit par appeler l'appel système execve(2).

Tu ne te rappelles plus le nom de la fonction qui « duplique un descripteur ». Comment la trouver ?

man -k duplicate (ou apropos duplicate) → dup (2) - duplicate a file descriptor.

Si man -k ne trouve rien

L'index n'est peut-être pas construit sur la machine (mandb pas lancé). Passe par man 2 syscalls ou par la rubrique SEE ALSO d'une page proche.

TD 1

Appels système, erreurs et environnement

Dans man : man 2 write man 3 errno man 3 perror man 3 strerror man 3 getenv man 7 environ man 3 pathconf man 3 getpwnam

En deux phrases

Un appel système est une demande faite au noyau (écrire, ouvrir un fichier, créer un processus…). En cas d'échec il renvoie presque toujours -1 et range un numéro d'erreur dans la variable globale errno.

Gérer une erreur, étape par étape

  1. Faire l'appel et stocker son retour : ret = write(...).
  2. Tester ret == -1 (ou NULL pour les fonctions qui renvoient un pointeur).
  3. Copier errno tout de suite dans une variable : le moindre appel suivant peut l'écraser.
  4. Afficher : perror("contexte") écrit « contexte: message » sur la sortie d'erreur. Ou fais-le à la main avec strerror(errno), qui renvoie le texte.
erreur.c · exercices 2 à 4
#include <stdio.h>    // printf, fprintf, perror
#include <string.h>   // strerror
#include <errno.h>    // la variable globale errno
#include <unistd.h>   // write

int main(void) {
    // 42 n'est pas un descripteur ouvert -> l'appel système échoue
    ssize_t ret = write(42, "hello\n", 6);

    if (ret == -1) {                 // -1 = échec, errno a été rempli
        int e = errno;               // on SAUVE errno tout de suite :
                                     // le prochain appel peut l'écraser
        perror("write");             // -> write: Bad file descriptor

        // Équivalent "fait main" : strerror traduit le code en texte
        fprintf(stderr, "Mon perror : %s (errno=%d)\n", strerror(e), e);
        return 1;
    }
    return 0;
}
Exercice 1 en une ligne

syscall(SYS_write, STDOUT_FILENO, "hello\n", 6); appelle le noyau directement par son numéro. write(1, "hello\n", 6) fait la même chose via une petite fonction de la libc. Le 6 = 5 lettres + '\n'.

Variables d'environnement

extern char **environ; est un tableau de chaînes "NOM=valeur" qui se termine par NULL. getenv("HOME") renvoie juste la partie valeur, ou NULL si la variable n'existe pas. putenv("X=1") ajoute ou modifie une variable.

monenv.c · exercices 6 et 7
#include <stdio.h>
#include <stdlib.h>   // getenv

extern char **environ;   // tableau de chaînes "NOM=valeur", terminé par NULL

int main(int argc, char *argv[]) {
    if (argc < 2) {                        // pas d'argument : on imite "env"
        for (char **p = environ; *p != NULL; p++)
            printf("%s\n", *p);
        return 0;
    }
    char *valeur = getenv(argv[1]);        // ex : ./monenv HOME
    if (valeur == NULL) {                  // la variable n'existe pas
        fprintf(stderr, "%s : variable inconnue\n", argv[1]);
        return 1;
    }
    printf("%s=%s\n", argv[1], valeur);
    return 0;
}

Limites du système et comptes utilisateurs

  • long pathconf(const char *path, int name) donne une limite qui dépend du fichier : _PC_LINK_MAX (nb max de liens), _PC_NAME_MAX (longueur d'un nom), _PC_PATH_MAX. Renvoie -1 si erreur ou si pas de limite.
  • getpwnam(login) et getpwuid(uid) renvoient un struct passwd * (champs pw_name, pw_uid, pw_gid, pw_gecos, pw_dir, pw_shell), ou NULL si inconnu.

stat, types de fichiers, droits et ls -lR

Dans man : man 2 stat man 3type stat man 7 inode man 3 opendir man 3 readdir man 3 getpwuid man 3 getgrgid man 3 strftime

En deux phrases

stat(chemin, &st) remplit une structure struct stat avec tout ce que l'i-nœud sait du fichier : type, droits, taille, propriétaire, dates. Pour lister un répertoire on utilise opendir, puis readdir en boucle, puis closedir.

Lire les droits : le masque binaire

st_mode est un nombre dont chaque bit veut dire quelque chose. st_mode & S_IWGRP garde uniquement le bit « écriture pour le groupe » : le résultat est non nul si le droit existe. Les droits en octal : r = 4, w = 2, x = 1, un chiffre pour propriétaire / groupe / autres. Exemple : 0754 = rwx r-x r--.

mon_ls.c · version courte et commentée du TD 2
#include <stdio.h>
#include <string.h>
#include <dirent.h>     // opendir, readdir, closedir
#include <sys/stat.h>   // lstat, S_ISDIR...

// Affiche type + droits comme "ls -l" : ex. drwxr-xr-x
void affiche_droits(mode_t m) {
    char type = '?';
    if      (S_ISREG(m))  type = '-';   // fichier ordinaire
    else if (S_ISDIR(m))  type = 'd';   // répertoire
    else if (S_ISLNK(m))  type = 'l';   // lien symbolique (lstat seulement !)
    else if (S_ISCHR(m))  type = 'c';   // périphérique caractère
    else if (S_ISBLK(m))  type = 'b';   // périphérique bloc
    else if (S_ISFIFO(m)) type = 'p';   // tube nommé
    else if (S_ISSOCK(m)) type = 's';   // socket

    // m & S_IRUSR est NON NUL si le bit "lecture propriétaire" est à 1
    printf("%c%c%c%c%c%c%c%c%c%c", type,
           m & S_IRUSR ? 'r' : '-', m & S_IWUSR ? 'w' : '-', m & S_IXUSR ? 'x' : '-',
           m & S_IRGRP ? 'r' : '-', m & S_IWGRP ? 'w' : '-', m & S_IXGRP ? 'x' : '-',
           m & S_IROTH ? 'r' : '-', m & S_IWOTH ? 'w' : '-', m & S_IXOTH ? 'x' : '-');
}

// Parcours RÉCURSIF d'un répertoire (comme ls -lR)
void parcours(const char *chemin) {
    DIR *d = opendir(chemin);              // 1) ouvrir le répertoire
    if (d == NULL) { perror(chemin); return; }

    struct dirent *e;
    while ((e = readdir(d)) != NULL) {     // 2) une entrée à chaque appel
        // ignorer "." et ".." sinon boucle infinie !
        if (strcmp(e->d_name, ".") == 0 || strcmp(e->d_name, "..") == 0)
            continue;

        char complet[4096];                // 3) construire "chemin/nom"
        snprintf(complet, sizeof(complet), "%s/%s", chemin, e->d_name);

        struct stat st;
        if (lstat(complet, &st) == -1) { perror(complet); continue; }

        affiche_droits(st.st_mode);
        printf(" %8ld %s\n", (long)st.st_size, complet);

        if (S_ISDIR(st.st_mode))           // 4) sous-répertoire -> on descend
            parcours(complet);
    }
    closedir(d);                           // 5) toujours fermer
}

int main(int argc, char *argv[]) {
    parcours(argc > 1 ? argv[1] : ".");
    return 0;
}
Ce que fait ta correction en plus

Elle parcourt chaque répertoire deux fois : un premier readdir pour tout afficher, puis rewinddir(dp) pour revenir au début et descendre dans les sous-répertoires. On obtient ainsi l'ordre de ls -lR : tout le contenu d'un dossier, puis les sous-dossiers.

Pièges
  • stat suit les liens symboliques : avec lui, S_ISLNK n'est jamais vrai. Il faut lstat pour voir le lien lui-même.
  • Oublier d'ignorer . et .. dans un parcours récursif donne une boucle infinie.
  • d_name ne contient que le nom : il faut construire "chemin/nom" avec snprintf avant d'appeler lstat.
  • Dans ta correction, char pws[9] puis strcpy(pws, pw->pw_name) déborde si le login fait plus de 8 lettres. Version sûre : snprintf(pws, sizeof(pws), "%s", pw->pw_name).

Système de fichiers et i-nœuds

Dans man : man 7 inode man 2 link man 2 symlink man 2 unlink man 2 rename

En deux phrases

Un fichier = un i-nœud (type, taille, nb de liens, liste des blocs) + des blocs de données. Le nom n'est pas dans l'i-nœud : il est stocké dans le bloc du répertoire parent, sous forme de paires (nom, n° d'i-nœud).

Exercice 1 · arborescence, place libre, fragmentation
/            (i-nœud 0)
├── toto/    (1)
│   ├── a.txt  (2)
│   └── b.txt  (5)
└── tata/    (3)
    └── c.txt  (7)

Place libre : 3 blocs libres (2, 8, 9) × 1024 = 3072 octets.

Fragmentation interne = ce qui est perdu à la fin du dernier bloc de chaque fichier :

  • a.txt : 2 × 1024 − 1900 = 148
  • b.txt : 1024 − 16 = 1008
  • c.txt : 1024 − 20 = 1004
  • Total : 2160 octets (les répertoires ont une taille de 1024, ils n'en perdent pas)

Vérifier les liens : « / » a 4 liens = son . + son .. + le .. de toto + le .. de tata. Un répertoire sans sous-répertoire a toujours 2 liens (son nom dans le parent + son .).

  • b.txt (16 octets, bloc 7) : bonjour\nbonjour\n (2 × 8 = 16 ✓).
  • c.txt (20 octets, bloc 6) : les lignes 12345, 67890, 67890.
Exercice 3 · blocs à lire pour trouver l'i-nœud de /toto/a.txt
  1. i-nœud 0 (racine, connu d'avance) → lire le bloc 0 → on y trouve toto 1.
  2. i-nœud 1 → lire le bloc 1 → on y trouve a.txt 2.

Lien physique vs symbolique

ln a b (physique) ajoute un nom vers le même i-nœud, dont le compteur de liens augmente. ln -s a b crée un nouvel i-nœud qui contient juste le chemin « a ». Si on supprime a, le lien physique marche toujours, le symbolique est cassé.

// Exercice 6 : afficher le contenu du fichier de l'i-noeud n
// Rappel du modèle : num_bloc[0] = NOMBRE de blocs,
//                    num_bloc[1..] = numéros des blocs
void print(int n) {
    int nb_blocs = table[n].num_bloc[0];
    int reste    = table[n].taille;          // octets qu'il reste à afficher

    for (int i = 1; i <= nb_blocs; i++) {
        int b = table[n].num_bloc[i];        // numéro du i-ème bloc
        int a_lire = (reste < TMAX) ? reste : TMAX;  // dernier bloc : pas plein
        for (int k = 0; k < a_lire; k++)
            putchar(blocs[b][k]);
        reste -= a_lire;
    }
}

// Exercice 7 : numéro d'i-noeud de "name" dans le répertoire d'i-noeud rep
// Un bloc de répertoire contient des lignes "nom numero\n"
int get_num_inode(int rep, char *name) {
    if (table[rep].type != 0) return -1;     // ce n'est pas un répertoire

    int nb_blocs = table[rep].num_bloc[0];
    for (int i = 1; i <= nb_blocs; i++) {
        char copie[TMAX + 1];
        strncpy(copie, blocs[table[rep].num_bloc[i]], TMAX);
        copie[TMAX] = '\0';                  // strtok modifie la chaîne : on copie

        char *ligne = strtok(copie, "\n");   // découpe ligne par ligne
        while (ligne != NULL) {
            char nom[TMAX]; int num;
            if (sscanf(ligne, "%s %d", nom, &num) == 2
                && strcmp(nom, name) == 0)
                return num;                  // trouvé !
            ligne = strtok(NULL, "\n");
        }
    }
    return -1;                               // pas trouvé
}

Fichiers : open, read, write, lseek

Dans man : man 2 open man 2 read man 2 write man 2 lseek man 2 close man 2 access man 2 creat

En deux phrases

open renvoie un descripteur : un petit entier (0 = entrée standard, 1 = sortie, 2 = erreur, puis 3, 4…). Ensuite read et write lisent ou écrivent à partir de la position courante (l'offset), qui avance à chaque appel et que lseek déplace.

Drapeau de openEffet
O_RDONLY / O_WRONLY / O_RDWRlecture seule / écriture seule / les deux (un seul des trois)
O_CREATcrée le fichier s'il n'existe pas. Exige le 3e argument : les droits, ex. 0644
O_TRUNCvide le fichier à l'ouverture
O_APPENDchaque write se fait à la fin
O_EXCL (avec O_CREAT)échoue si le fichier existe déjà

Valeurs de retour de read : nombre d'octets lus (peut être moins que demandé), 0 = fin de fichier, -1 = erreur. C'est ce qui permet la boucle while ((n = read(...)) > 0).

#include <stdio.h>
#include <fcntl.h>    // open, O_RDONLY, O_WRONLY...
#include <unistd.h>   // read, write, close, access

#define TAILLE 4096

int main(int argc, char *argv[]) {
    // 1) Vérifier le nombre d'arguments
    if (argc != 3) {
        fprintf(stderr, "usage : %s source destination\n", argv[0]);
        return 1;
    }
    // 2) Le fichier source est-il lisible ?
    if (access(argv[1], R_OK) == -1) { perror(argv[1]); return 1; }

    // 3) Ouvrir la source en lecture
    int src = open(argv[1], O_RDONLY);
    if (src == -1) { perror("open source"); return 1; }

    // 4) Créer/vider la destination (droits rw-r--r-- = 0644)
    //    open échoue si le répertoire n'est pas accessible en écriture
    int dst = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (dst == -1) { perror("open destination"); close(src); return 1; }

    // 5) Boucle lire -> écrire jusqu'à la fin du fichier (read renvoie 0)
    char buf[TAILLE];
    ssize_t n;
    while ((n = read(src, buf, TAILLE)) > 0) {
        if (write(dst, buf, n) != n) { perror("write"); return 1; }
    }
    if (n == -1) perror("read");

    // 6) Toujours fermer
    close(src);
    close(dst);
    return 0;
}

#include <fcntl.h>
#include <unistd.h>

// Pose (ou enlève) un verrou sur une zone du fichier fd
int lock_reg(int fd, int cmd, int type, off_t offset, int whence, off_t len) {
    struct flock lock;
    lock.l_type   = type;    // F_RDLCK (lecture), F_WRLCK (écriture), F_UNLCK
    lock.l_start  = offset;  // début de la zone, relatif à whence
    lock.l_whence = whence;  // SEEK_SET, SEEK_CUR ou SEEK_END
    lock.l_len    = len;     // nb d'octets (0 = jusqu'à la fin du fichier)
    return fcntl(fd, cmd, &lock);  // cmd : F_SETLK ou F_SETLKW
}

// F_SETLK  = NON bloquant : échoue tout de suite (-1, errno=EAGAIN/EACCES)
// F_SETLKW = bloquant (W = Wait) : attend que le verrou soit libre
#define read_lock(fd, o, w, l)   lock_reg(fd, F_SETLK,  F_RDLCK, o, w, l)
#define readw_lock(fd, o, w, l)  lock_reg(fd, F_SETLKW, F_RDLCK, o, w, l)
#define write_lock(fd, o, w, l)  lock_reg(fd, F_SETLK,  F_WRLCK, o, w, l)
#define writew_lock(fd, o, w, l) lock_reg(fd, F_SETLKW, F_WRLCK, o, w, l)
#define un_lock(fd, o, w, l)     lock_reg(fd, F_SETLK,  F_UNLCK, o, w, l)

  • Les verrous fcntl sont consultatifs : un processus qui ne demande pas de verrou peut quand même écrire.
  • Les verrous ne sont pas hérités par le fils après fork et disparaissent quand le processus se termine ou ferme le fichier.

mmap : un fichier vu comme un tableau

mmap place le contenu du fichier dans la mémoire du processus et renvoie un pointeur. On lit et écrit alors avec adr[i] au lieu de read/write. Avec MAP_SHARED, une modification en mémoire est écrite dans le fichier (réponse de l'exo 7) et visible par les autres processus. Avec MAP_PRIVATE, elle reste une copie privée.

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>   // mmap, munmap
#include <sys/stat.h>   // fstat

int main(void) {
    // O_RDWR obligatoire pour PROT_WRITE + MAP_SHARED
    int fd = open("test.dat", O_RDWR);
    if (fd == -1) { perror("open"); exit(1); }

    struct stat st;
    fstat(fd, &st);                       // taille réelle du fichier

    char *adr = mmap(NULL, st.st_size,    // NULL : le noyau choisit l'adresse
                     PROT_READ | PROT_WRITE,
                     MAP_SHARED,          // modifs répercutées DANS le fichier
                     fd, 0);              // à partir de l'octet 0
    if (adr == MAP_FAILED) { perror("mmap"); exit(2); }

    printf("Avant : %.*s\n", (int)st.st_size, adr);
    adr[1] = 'e';                         // on écrit en mémoire...
    printf("Après : %.*s\n", (int)st.st_size, adr);
    // ... et le fichier test.dat est modifié lui aussi !

    munmap(adr, st.st_size);
    close(fd);
    return 0;
}
Piège de la correction

Elle ouvre avec O_RDONLY | 0666 puis demande PROT_WRITE + MAP_SHARED : mmap échoue (EACCES). Il faut O_RDWR. Le 0666 n'a rien à faire dans les drapeaux, c'est un 3e argument. Et mmap renvoie MAP_FAILED, pas NULL, en cas d'erreur.

TD 6

Processus : fork et wait

Dans man : man 2 fork man 2 wait man 2 getpid man 2 pread

En deux phrases

fork() crée une copie presque identique du processus. Les deux continuent le code juste après fork ; seule la valeur renvoyée les distingue : 0 dans le fils, le PID du fils dans le père, -1 en cas d'échec.

  1. Le père appelle fork().
  2. if (pid == 0) : code du fils, qui finit par exit(code).
  3. Sinon : code du père, qui appelle wait(&status) pour attendre et « ramasser » le fils.
  4. WIFEXITED(status) est vrai si le fils a fini normalement ; WEXITSTATUS(status) donne alors son code (0 à 255).
fork.c · exercices 1 et 4
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>     // fork, getpid, getppid, sleep
#include <sys/wait.h>   // wait, WIFEXITED, WEXITSTATUS

int main(void) {
    printf("[%d] Je vais engendrer\n", getpid());

    fflush(stdout);              // vider le tampon AVANT fork (voir pièges)
    pid_t pid = fork();          // à partir d'ici : 2 processus exécutent la suite

    if (pid == -1) {             // échec (trop de processus...)
        perror("fork");
        exit(EXIT_FAILURE);
    }
    if (pid == 0) {              // ===== FILS : fork a renvoyé 0 =====
        printf("[%d] Fils, mon père est %d\n", getpid(), getppid());
        sleep(2);
        exit(7);                 // code de retour choisi : 7
    }
    // ===== PÈRE : fork a renvoyé le PID du fils =====
    printf("[%d] Père, mon fils est %d\n", getpid(), pid);

    int status;
    pid_t fini = wait(&status);  // bloque jusqu'à la fin d'UN fils
    if (WIFEXITED(status))       // terminé normalement (exit / return) ?
        printf("[%d] Fils %d fini, code = %d\n",
               getpid(), fini, WEXITSTATUS(status));   // -> 7
    else
        printf("Fils terminé anormalement (signal)\n");
    return 0;
}

Ordre d'apparition (exo 1) : après fork, c'est l'ordonnanceur qui décide qui s'exécute d'abord. On ne peut jamais supposer que le père ou le fils affiche en premier. Seul wait garantit que le père termine après le fils.

Fichier ouvert avant fork (exos 2 et 3)

Le fils reçoit une copie des descripteurs, mais ils pointent vers la même entrée de la table des fichiers ouverts que ceux du père. Ils partagent donc le même offset.

  1. Le père lit 2 octets avant le fork : l'offset partagé vaut 2.
  2. Le premier qui écrit (disons le père, « bar ») écrit aux octets 2 à 4 ; l'offset passe à 5.
  3. Le fils écrit « foo » aux octets 5 à 7 ; offset = 8.
  4. Le père relit après 1 s à partir de 8, le fils après 2 s à partir de 11 : aucun ne relit ce qu'il a écrit.

Orphelins, zombies et exec

Dans man : man 2 execve man 3 exec man 3 exit man 2 _exit
Orphelin

Le père meurt avant le fils. Le fils est adopté par init (PID 1), ou par un « subreaper » comme systemd --user sur les Linux récents. Usage (exo 2) : les démons (serveurs en arrière-plan) se détachent ainsi du terminal.

Zombie

Le fils est mort mais le père, toujours vivant, n'a pas fait wait. Le noyau garde son entrée (PID + code de retour). Visible avec ps aux : état Z, <defunct>. Danger (exo 5) : chaque zombie occupe un PID, assez de zombies et plus aucun processus ne peut être créé.

#include <stdio.h>

#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

#define MAX 256

int main(void) {
    char ligne[MAX];
    char *args[MAX / 2];

    while (1) {
        printf("mini-shell> ");
        fflush(stdout);                        // afficher le prompt maintenant
        if (fgets(ligne, MAX, stdin) == NULL) break;   // Ctrl-D
        ligne[strcspn(ligne, "\n")] = '\0';    // enlever le '\n' final

        // Découper la ligne en mots : "ls -l /tmp" -> {"ls","-l","/tmp",NULL}
        int n = 0;
        char *mot = strtok(ligne, " ");
        while (mot != NULL) {
            args[n++] = mot;
            mot = strtok(NULL, " ");
        }
        args[n] = NULL;                        // exec exige un NULL final
        if (n == 0) continue;                  // ligne vide
        if (strcmp(args[0], "exit") == 0) break;

        pid_t pid = fork();
        if (pid == -1) { perror("fork"); continue; }
        if (pid == 0) {                        // FILS : devient la commande
            execvp(args[0], args);             // p = cherche dans le PATH
            perror(args[0]);                   // seulement si exec a échoué
            exit(127);
        }
        int status;                            // PÈRE : attend la fin
        waitpid(pid, &status, 0);
    }
    return 0;
}
Pourquoi fork avant exec ?

Si le shell appelait exec directement, il serait remplacé par la commande et disparaîtrait. Le fils se « sacrifie » pour devenir la commande, le père survit et attend.

Redirections : dup2 dans le mini-shell

Dans man : man 2 dup man 3 exec man 2 open

En deux phrases

Une commande comme echo écrit toujours sur le descripteur 1, sans savoir où il mène. dup2(fd, 1) fait pointer le descripteur 1 vers le même fichier que fd : tout ce qui allait à l'écran va désormais dans le fichier.

  1. Le shell lit /bin/echo toto > test et repère le > et le nom test.
  2. fork().
  3. Dans le fils : open("test", O_WRONLY|O_CREAT|O_TRUNC, 0644), puis dup2(fd, STDOUT_FILENO), puis close(fd).
  4. Toujours dans le fils : execv. La commande hérite du descripteur 1 redirigé.
  5. Le père n'a rien redirigé : il fait wait et réaffiche le prompt normalement.

En deux phrases

Les fonctions de la libc (calloc, printf, fopen…) sont construites au-dessus des appels système (sbrk, write, open…). Leur astuce principale : un tampon en mémoire, pour faire peu d'appels système, qui coûtent cher.

Mémoire : sbrk et une liste chaînée

  1. sbrk(n) agrandit le tas de n octets et renvoie l'ancienne fin du tas, qui est donc le début de la nouvelle zone. Échec : (void*)-1.
  2. On garde une liste de toutes les zones données (adresse, taille, libre ou utilisée).
  3. mini_free ne rend rien au système : elle marque la zone libre (exo 6 : le vrai free non plus, en général).
  4. mini_calloc réutilise d'abord une zone libre assez grande, sinon appelle sbrk. Elle remet tout à zéro, car une zone réutilisée contient les anciennes données (exo 5 : sécurité et valeurs prévisibles).
mini_memory.c · exercices 4 à 11
#include <unistd.h>    // sbrk, _exit

typedef struct malloc_element {
    void *zone;                        // adresse de la zone donnée à l'utilisateur
    int taille;                        // size_element * number_element
    int statut;                        // 0 = libre, 1 = utilisée
    struct malloc_element *next_malloc;// élément suivant (NULL = fin)
} malloc_element;

malloc_element *malloc_list = NULL;    // la liste est vide au départ

void *mini_calloc(int size_element, int number_element) {
    int taille = size_element * number_element;
    if (taille <= 0) return NULL;

    // 1) Chercher une zone LIBRE assez grande pour la réutiliser
    for (malloc_element *e = malloc_list; e != NULL; e = e->next_malloc) {
        if (e->statut == 0 && e->taille >= taille) {
            e->statut = 1;
            char *p = e->zone;
            for (int i = 0; i < taille; i++) p[i] = '\0';  // remise à zéro
            return e->zone;
        }
    }
    // 2) Sinon : agrandir le tas avec sbrk (renvoie l'ANCIENNE fin du tas)
    char *p = sbrk(taille);
    if (p == (void *)-1) return NULL;  // échec de sbrk
    for (int i = 0; i < taille; i++) p[i] = '\0';  // calloc = mémoire à 0

    // 3) Mémoriser la zone dans la liste (l'élément aussi vient de sbrk)
    malloc_element *e = sbrk(sizeof(malloc_element));
    if (e == (void *)-1) return NULL;
    e->zone = p;
    e->taille = taille;
    e->statut = 1;
    e->next_malloc = malloc_list;      // ajout en tête de liste
    malloc_list = e;
    return p;
}

void mini_free(void *ptr) {
    // On ne rend RIEN au système : on marque juste la zone comme libre
    for (malloc_element *e = malloc_list; e != NULL; e = e->next_malloc)
        if (e->zone == ptr) { e->statut = 0; return; }
}

mini_printf : écriture tamponnée

mini_string.c · exercices 15 à 18
#include <unistd.h>    // write

#define BUF_SIZE 1024
char *buffer = NULL;   // le tampon
int ind = -1;          // -1 = tampon pas encore alloué

void mini_printf(char *msg) {
    if (ind == -1) {                         // premier appel : allocation
        buffer = mini_calloc(sizeof(char), BUF_SIZE);
        ind = 0;
    }
    for (int i = 0; msg[i] != '\0'; i++) {
        buffer[ind++] = msg[i];              // on remplit le tampon
        if (ind == BUF_SIZE || msg[i] == '\n') {
            write(STDOUT_FILENO, buffer, ind);   // plein ou '\n' : on vide
            ind = 0;
        }
    }
}

void mini_exit(void) {
    // Problème de l'exo 17 : un texte SANS '\n' reste dans le tampon
    // -> on le vide avant de quitter
    if (ind > 0) write(STDOUT_FILENO, buffer, ind);
    _exit(0);                                // appel système brut
}
Exos 17-18 et 34

Un texte sans '\n' reste dans le tampon, et _exit quitte sans le vider : rien ne s'affiche. On corrige dans mini_exit en vidant le tampon (et en appelant mini_fflush sur chaque fichier ouvert). strace ./prog montre bien un seul write par ligne.

Sécurité des fonctions de chaînes (exo 22)

mini_strcpy(s, d) copie sans connaître la taille de d : débordement de tampon possible (buffer overflow), donc écrasement de la mémoire voisine. Correction : passer la taille, mini_strncpy(s, d, taille_d), copier au plus taille_d - 1 caractères et toujours finir par '\0'. Même chose pour mini_scanf (exo 20) : si on lit exactement size_buffer caractères, il n'y a plus de place pour le '\0', donc lire au plus size_buffer - 1.

MYFILE : lecture tamponnée

mini_io.c · exercices 27 à 29
#include <fcntl.h>
#include <unistd.h>

#define IOBUFFER_SIZE 2048

typedef struct MYFILE {
    int fd;
    void *buffer_read;
    void *buffer_write;
    int ind_read;          // -1 = buffer pas encore alloué
    int ind_write;
    int nb_read;           // (ajout perso) nb d'octets valides dans buffer_read
} MYFILE;

MYFILE *mini_fopen(char *file, char mode) {
    int flags;
    switch (mode) {
        case 'r': flags = O_RDONLY;                      break;
        case 'w': flags = O_WRONLY | O_CREAT | O_TRUNC;  break;
        case 'b': flags = O_RDWR   | O_CREAT;            break;
        case 'a': flags = O_WRONLY | O_CREAT | O_APPEND; break;
        default:  return NULL;                           // mode inconnu
    }
    int fd = open(file, flags, 0644);
    if (fd == -1) return NULL;

    MYFILE *f = mini_calloc(sizeof(MYFILE), 1);
    f->fd = fd;
    f->buffer_read = NULL;  f->ind_read = -1;
    f->buffer_write = NULL; f->ind_write = -1;
    return f;
}

int mini_fread(void *buffer, int size_element, int number_element, MYFILE *f) {
    if (f->ind_read == -1) {                     // premier appel
        f->buffer_read = mini_calloc(1, IOBUFFER_SIZE);
        f->ind_read = 0;
        f->nb_read = 0;
    }
    char *dst = buffer, *src = f->buffer_read;
    int voulu = size_element * number_element, copie = 0;

    while (copie < voulu) {
        if (f->ind_read == f->nb_read) {             // buffer épuisé -> UN read
            f->nb_read = read(f->fd, src, IOBUFFER_SIZE);
            if (f->nb_read == -1) return -1;     // erreur
            if (f->nb_read == 0) break;              // fin de fichier
            f->ind_read = 0;
        }
        dst[copie++] = src[f->ind_read++];       // copie octet par octet
    }
    return copie;                                // nb de caractères lus
}

mini_fwrite marche en miroir : on copie dans buffer_write, et on ne fait le write que quand il est plein. mini_fflush écrit ce qui reste (ind_write octets) et remet l'index à 0. mini_fclose = mini_fflush + retirer de la liste des fichiers ouverts + close.

Pièges classiques à l'examen

vérifiés en compilant les codes de cette page
printf puis fork

Si la sortie est redirigée (fichier, pipe), printf garde le texte en tampon. Le fork copie ce tampon : le texte sort deux fois. Remède : fflush(stdout) juste avant fork. Testé pendant la préparation de cette page.

errno écrasé

En testant perror puis strerror(errno), la 2e ligne affichait « Invalid argument » au lieu de « Bad file descriptor » : perror avait modifié errno. Sauve-le dans une variable dès l'échec.

Oublier le NULL d'exec

Le tableau d'arguments doit finir par NULL, sinon exec lit n'importe quoi. Et argv[0] = le nom du programme, pas le 1er argument.

Tester le mauvais retour

mmap échoue avec MAP_FAILED, sbrk avec (void*)-1, opendir/getenv/getpwnam avec NULL, les autres avec -1.

Droits en décimal

open(f, O_CREAT|O_WRONLY, 644) sans le 0 devant = 644 en décimal = droits absurdes. Écris 0644.

wait oublié

Sans wait, le fils fini devient zombie, et le père peut réafficher le prompt avant que la commande ait fini.

cd dans un fils

Une commande interne (cd, export, exit) doit être traitée par le père, sans fork : un fils qui change de dossier ne change rien pour le shell.

Ordre père / fils

« Le père s'affiche toujours en premier » est faux. Toute réponse qui dépend de l'ordre d'exécution sans wait, sleep ou verrou doit dire que l'ordre n'est pas garanti.

Squelette fork + exec + wait à savoir par cœur
squelette
pid_t pid = fork();
if (pid == -1) { perror("fork"); exit(1); }
if (pid == 0) {                     // fils
    execvp(args[0], args);          // args finit par NULL
    perror("exec");                 // seulement si échec
    exit(127);
}
int status;                         // père
waitpid(pid, &status, 0);
if (WIFEXITED(status)) printf("code %d\n", WEXITSTATUS(status));
